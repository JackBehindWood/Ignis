# Ignis Build System

Python package (`build/`) invoked via `python3 -m build`. Root `GNUmakefile` wraps all targets so you can just type `make`.

## Quick start

```bash
# Fresh checkout — one command from zero to working dev environment:
make bootstrap
# or: python3 -m build bootstrap

# Day-to-day:
make          # build (Debug)
make run      # run
make br       # build + run
make clean    # wipe bin/, bin-int/, compile_commands

# Release builds:
make release  # CONFIG=Release
make dist     # CONFIG=Distribution
# or: make CONFIG=Release
```

## Commands

### `make` targets

| Target | Description |
|---|---|
| `make` / `make build` | Generate Makefiles + compile (Debug) |
| `make run` | Run the compiled executable |
| `make br` | Build then run |
| `make clean` | Remove `bin/`, `bin-int/`, compile commands |
| `make release` | Release build |
| `make dist` | Distribution build |
| `make setup` | Install/update premake + DXC |
| `make setup-hooks` | Install git pre-commit hooks |
| `make bootstrap` | Fresh checkout → working dev env in one shot |
| `make doctor` | Check all prerequisites and print ✓/✗ status |
| `make vscode` | Regenerate `.vscode/` files |
| `make test` | Run test suite |

Pass `CONFIG=Release` to any target: `make build CONFIG=Release`.

| Command | Flags | Description |
|---|---|---|
| `init` | `--force --yes` | Scaffold `config.ini`; `--yes` skips all prompts |
| `bootstrap` | | `init` (if missing) + `setup` + `build` in one shot |
| `doctor` | | Print ✓/✗ for every prerequisite |
| `setup` | `--update` | Install/update premake and vendor dependencies |
| `build` | `--clean --dev --no-dev --config <cfg> --verbose` | Generate build files and compile |

| `build-run` | _(same as build)_ | Build then run |
| `clean` | | Remove `bin/`, `bin-int/`, and compile commands |

`--config` choices: `Debug` (default) · `Release` · `Distribution`

## Plugin system

All optional tooling is a plugin. Enable one by listing it in `config.ini`.

| name | type | what it does |
|---|---|---|
| `export-compile-commands` | `premake` | Generates per-config `compile_commands.json` files |
| `vscode` | `vscode` | Syncs `.vscode/` on explicit `make vscode` |
| `clangd` | `python` | Creates root `compile_commands.json` symlink for clangd auto-discovery |

**Plugin types:**
- **`premake`** — Lua module cloned into `premake/plugins/`. Runs as a premake action at generation time.
- **`python`** — Built-in Python module in `build/plugins/`. No install step; activated by appearing in `config.ini`.
- **`vscode`** — Subclass of `python`; owns `makefile_tools` / `build_log` config fields.

```bash
python3 -m build plugin list
python3 -m build plugin install export-compile-commands
python3 -m build plugin update --all
```

## config.ini reference

Generated by `python3 -m build init` or `init --yes`. Gitignored — do not commit.

```ini
[build]
generator     = gmake          # gmake | gmake2 | xcode4 | vs2022 | vs2019
configuration = Debug          # Debug | Release | Distribution
verbose       = false
dev           = true           # generate compile_commands on every build
bin_dir       = bin
obj_dir       = bin-int

[premake]
dir        = premake
exec       = premake/premake5
file       = premake5.lua
version    = 5.0.0-beta8
plugin_dir = premake/plugins

[project]
exec_name = IgnisEditor        # auto-detected from premake5.lua during init
name      = Ignis Editor       # display name (used in VS Code launch configs)
run_dir   =                    # CWD when launching (relative to project root; blank = root)
run_args  =                    # space-separated args forwarded on launch

[plugin.export-compile-commands]
type = premake
url  = https://github.com/tarruda/premake-export-compile-commands

[plugin.vscode]
type = python

[plugin.clangd]
type = python
```

## Compile commands (IntelliSense / clangd)

With `export-compile-commands` installed and dev mode on, every build:

> **`.vscode/` is only regenerated on explicit `make vscode` (or `python3 -m build vscode`) — not on every dev build.**

1. Runs `premake export-compile-commands` → `compile_commands/{debug,release,distribution}.json` at root
2. Moves that directory to `premake/output/compile_commands/`
3. _(if `clangd` plugin enabled)_ Creates `compile_commands.json` symlink at root → `debug.json`

`.vscode/c_cpp_properties.json` points each named config to its per-config file so clangd in VSCode always has the right flags.

## Build hooks

Drop `build/hooks/pre_build.py` or `post_build.py` with a `run(ctx)` function. `ctx` exposes: `project_dir`, `bin_dir`, `obj_dir`, `configuration`, `verbose`.

## DXC setup (macOS)

Requires the [LunarG Vulkan SDK](https://vulkan.lunarg.com/sdk/home#mac). Install it, then run `make setup`. The script auto-detects the SDK via `$VULKAN_SDK` or `~/VulkanSDK/`. Force reinstall with `make setup` after editing `config.ini` or `python3 -m build setup --update`.

## Pre-commit hooks

```bash
make setup-hooks
```

Installs `.githooks/pre-commit`: runs `clang-format -i` on staged `.cpp`/`.h`/`.mm` files and re-stages them automatically. Commit proceeds with formatted code — no manual fix step. Requires `clang-format` (`brew install clang-format`); silently skips if not installed.

Formatting rules are defined in `.clang-format` at the repo root (Allman braces, 4-space indent, `InsertBraces: true` to enforce curly braces on all control flow).

## File layout

```
build/
  __init__.py
  __main__.py         entry point — argument parsing + command dispatch
  core/
    __init__.py
    constants.py      path roots, CONFIGURATIONS, GENERATORS
    config.py         Config singleton; config.ini I/O
    utils.py          run_command, prompts, download_file, gitignore helpers
  commands/
    __init__.py
    build.py          generate Makefiles + compile; compile_commands flow
    run.py            launch the compiled binary
    setup.py          orchestrate premake + DXC setup
  setup/
    __init__.py
    premake.py        download + install premake5
    dxc.py            download + install DXC from Vulkan SDK
  plugins/
    __init__.py       re-exports from plugin.py
    plugin.py         BasePlugin, PremakePlugin, PythonPlugin, VscodePlugin, PluginManager
    vscode.py         generates/syncs .vscode/ configuration files
    clangd.py         creates compile_commands.json symlink for clangd
  hooks/              pre_build.py / post_build.py hooks
  config.ini          generated by init — gitignored
GNUmakefile           dev wrapper (GNU Make picks this over premake's Makefile)
```

## core/utils.py API

| Function | Description |
|---|---|
| `run_command(cmd, cwd, verbose)` | Subprocess; exits on failure |
| `require_tool(name)` | Assert tool on `$PATH`; exit if not |
| `download_file(url, dest)` | curl download |
| `prompt / prompt_bool / prompt_list` | Interactive prompts used by `init` |
| `update_gitignore(path, entries, marker)` | Append a marked block to `.gitignore` |
| `ensure_gitignored(path, entry, comment)` | Append a single entry to `.gitignore` |

## Next steps / roadmap

> Currently the only supported build file generator is **premake5 → GNU Make**.

### Potential generator expansion
- **Xcode** (`xcode4`): premake supports it natively — wire up `make xcode` and a corresponding `python3 -m build build --generator xcode4`.
- **Ninja**: premake does not ship a Ninja generator; would need a third-party premake plugin or a hand-rolled `build/ninja.py` that emits `build.ninja` from the premake project graph.
- **CMake**: a full port away from premake — high effort, not planned.

### CI / automation
- Add a `make ci` target that runs `bootstrap --yes` + `build` + `test` non-interactively (no tty prompts, suitable for GitHub Actions).
- Cache `premake/premake5` and `engine/vendor/dxc/` between CI runs on the artifact store.

### Plugin ideas
- **`clang-tidy`** (python): run `clang-tidy` over changed files as a post-build step using the `compile_commands.json` symlink.
- **`ccache`** (python): prepend `ccache` to compiler invocations for faster incremental builds.
- **`iwyu`** (python): include-what-you-use pass on demand (`make iwyu`).

### Quality of life
- `make compile-commands` target: regenerate compile commands without a full rebuild (useful after adding files without changing source).
