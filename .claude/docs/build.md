# Build & Layout

```bash
# Invoke via python -m (required — enables relative imports):
python3 -m build build           # generate Makefiles + build (Debug)
python3 -m build build --clean
python3 -m build build --config Release
python3 -m build run
python3 -m build build-run
python3 -m build setup           # first-time project setup
python3 -m build setup-hooks     # install git/build hooks
python3 -m build vscode          # regenerate .vscode config (if vscode plugin enabled)
```

Premake5 (`premake/premake5`) → GNU Make. Configs: `Debug` | `Release` | `Distribution`. Output: `bin/` · `bin-int/`.

## Plugin System

All optional build tooling is managed through the plugin system, configured in `build/config.ini`.

### Plugin types

| type | install | description |
|------|---------|-------------|
| `premake` | `git clone` into `premake/plugins/` | Lua modules loaded by premake at generation time |
| `python`  | built-in (no install) | Python modules in `build/plugins/` — activated by listing in config.ini |
| `vscode`  | built-in (no install) | Subclass of `python`; owns `makefile_tools` / `build_log` config fields |

### Known plugins

| name | type | description |
|------|------|-------------|
| `export-compile-commands` | premake | Generates per-config `compile_commands.json` files via `premake export-compile-commands` |
| `vscode` | vscode | Generates/syncs `.vscode/` on explicit `make vscode` only — skipped during dev builds |
| `clangd` | python  | Creates a `compile_commands.json` symlink at project root → `premake/output/compile_commands/debug.json` for clangd auto-discovery |

Enable a plugin by adding it to `config.ini` (done automatically by `python3 -m build init`):

```ini
[plugin.export-compile-commands]
type = premake
url  = https://github.com/tarruda/premake-export-compile-commands

[plugin.vscode]
type = python

[plugin.clangd]
type = python
```

Manage via CLI:
```bash
python3 -m build plugin list
python3 -m build plugin install export-compile-commands
python3 -m build plugin update --all
```

### compile_commands flow

When `export-compile-commands` is installed and `--dev` is active (default in dev mode):

1. `premake export-compile-commands` generates `compile_commands/{debug,release,distribution}.json` at project root
2. Directory is moved to `premake/output/compile_commands/`
3. If `clangd` plugin is enabled: `compile_commands.json` symlink created at project root → `premake/output/compile_commands/debug.json`

`.vscode/c_cpp_properties.json` points each named config to its per-config file:
- Debug → `premake/output/compile_commands/debug.json`
- Release → `premake/output/compile_commands/release.json`
- Distribution → `premake/output/compile_commands/distribution.json`

## Entry points

| Entry point | When to use |
|-------------|-------------|
| `make` / `make build` | Day-to-day build (Debug) |
| `make bootstrap` | Fresh checkout — runs init + setup + build |
| `make doctor` | Check all prerequisites (premake, DXC, plugins, hooks) |
| `make setup` | Install/update premake + DXC |
| `make setup-hooks` | Install `.githooks/pre-commit` (clang-format dry-run gate) |
| `python3 -m build init [--yes]` | Scaffold `config.ini`; `--yes` skips all prompts |

## Generator

Only **premake5 → GNU Make** is supported. `GNUmakefile` is the dev wrapper at project root; GNU Make prefers it over the premake-generated `Makefile`. `build.py` invokes `make -f Makefile` explicitly to target the premake file and avoid recursion.

`CONFIG` choices passed to premake: `Debug` (default) · `Release` · `Distribution`.

## config.ini sections

| Section | Keys | Notes |
|---------|------|-------|
| `[build]` | `generator`, `configuration`, `verbose`, `dev`, `bin_dir`, `obj_dir` | All build output config in one place |
| `[premake]` | `dir`, `exec`, `file`, `version`, `plugin_dir` | All premake-related paths and version |
| `[project]` | `exec_name`, `name`, `run_dir`, `run_args` | `run_dir` is CWD on launch (relative); `run_args` space-separated |
| `[plugin.X]` | `type`, `url`, _(plugin-specific)_ | One section per enabled plugin |

## Build hooks

Drop `build/hooks/pre_build.py` or `post_build.py` with a `run(ctx)` function. `ctx` exposes: `project_dir`, `bin_dir`, `obj_dir`, `configuration`, `verbose`.
